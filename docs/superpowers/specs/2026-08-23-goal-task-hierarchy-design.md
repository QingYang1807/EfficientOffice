# 目标与任务层级管理改造设计

日期：2026-08-23
状态：已确认设计基线，待实施计划

## 1. 结论

采用“目标树 + 任务树”双树模型：目标可包含多层子目标；目标任务直属一个目标，并可包含多层子任务；普通任务可暂不归属目标。目标页与任务页双向展示完整归属路径，父级进度由直属子节点递归汇总。

## 2. 背景与证据

### 已确认事实

- 当前路由使用 `GoalManagement.vue`，目标保存于 localStorage 的 `goals`。
- 任务保存于 localStorage 的 `todos`，通过可选 `goalId`、`goalTitle` 松散关联目标。
- 目标页“关联任务”尚未实现；AI 生成任务会直接写入 `todos`。
- 项目同时存在另一套未启用的 `GoalManager.vue` 与两套任务 Store，模型及状态来源不统一。
- 当前目标、任务均无稳定的父子字段，无法表达多层结构。

### 用户确认需求

- 目标详情需要重新设计。
- 每个目标可独立创建关联任务。
- 任务管理需要显示上层目标。
- 支持多层目标和多层子任务。

## 3. 设计原则

1. **语义分离**：目标表达结果，任务表达行动，不抽象成无差别通用节点。
2. **单一归属**：一个目标最多一个父目标；一个任务最多一个父任务，且只直属一个目标。
3. **双向可达**：从目标可定位任务，从任务可定位完整目标路径。
4. **单一数据源**：目标与任务分别只有一个 Store，页面不直接维护独立副本。
5. **渐进迁移**：保留现有数据；无效关联显式暴露，不静默删除。
6. **防止失控**：数据结构支持任意层级，产品限制最大20层并阻止循环引用。

## 4. 方案取舍

### 方案A：统一工作项树

目标和任务使用同一节点模型，以类型区分。模型精简，但目标进度、任务完成、筛选和权限语义容易混杂，迁移风险较高。

### 方案B：目标树 + 任务树（采用）

目标通过 `parentGoalId` 成树；任务通过 `parentTaskId` 成树，并通过 `goalId` 归属目标。关系直观，兼容现有 `goalId`，实现成本可控。

### 方案C：通用关系图

允许多父级及任意关联。表达力最强，但循环、重复计数、删除语义和界面复杂度明显超出当前需求。

## 5. 领域模型

### 5.1 Goal

```ts
interface Goal {
  id: string
  parentGoalId: string | null
  title: string
  description: string
  manualProgress: number | null // 仅无下级的叶子目标使用
  weight: number // 同级汇总权重，默认1
  startDate: string | null
  deadline: string | null
  createdAt: string
  updatedAt: string
}
```

### 5.2 Task

```ts
interface Task {
  id: string
  goalId: string | null
  parentTaskId: string | null
  title: string
  description: string
  completed: boolean // 仅叶子任务是用户输入；父任务为派生值
  weight: number // 同级汇总权重，默认1
  priority: '高' | '中' | '低'
  deadline: string | null
  createdAt: string
  updatedAt: string
}
```

### 5.3 约束

- `parentGoalId` 必须指向存在且不同于自身的目标。
- `parentTaskId` 必须指向存在、不同于自身且 `goalId` 相同的任务。
- 移动节点前检查祖先链，禁止形成循环。
- 新建子任务继承父任务的 `goalId`，不可单独改为其他目标。
- 将父任务移动到其他目标时，其全部后代一起迁移。
- 目标和任务层级各不超过20层。
- 无目标任务允许存在，显示为“未归属目标”；目标内创建的任务必须带 `goalId`。
- `progress` 与 `status` 是 Store 计算出的视图字段，不作为持久化事实；避免缓存值与层级关系失配。

## 6. 进度与状态规则

### 6.1 任务进度

- 叶子任务：未完成为0%，完成为100%。
- 父任务：按直属子任务权重加权平均；不重复计算更深层后代。
- 父任务有子任务后，其 `completed` 由汇总结果派生，达到100%即完成。

### 6.2 目标进度

- 叶子目标且无直属任务：使用 `manualProgress`，默认0%。
- 目标存在直属子目标或直属根任务时：把两者作为同一级贡献项，按权重加权平均。
- 仅统计直属根任务，子任务已由根任务进度折算，避免重复计算。
- 无贡献项且未手填时为0%。

公式：

```text
progress = Σ(child.progress × child.weight) / Σ(child.weight)
```

### 6.3 状态

- 进度100%：`completed`。
- 未完成且截止时间早于当前时间：`overdue`。
- 进度大于0%：`in_progress`。
- 其他：`not_started`。

完成状态优先于逾期状态，避免已完成项目被标为逾期。

## 7. 信息架构与交互

### 7.1 目标管理：默认三栏工作台

**左栏：目标树**

- 展开/收起任意层级。
- 搜索标题；按状态、期限筛选。
- 节点显示标题、进度和状态。
- 节点菜单：新增子目标、新增任务、移动、编辑、删除。

**中栏：目标详情**

- 顶部展示完整面包屑、标题、状态、进度和期限。
- 展示描述、直属子目标、进度构成。
- 主要操作：新增子目标、新增任务、编辑目标。

**右栏：目标任务树**

- 只展示当前目标直属的任务树，不混入子目标的任务。
- 支持原地新增根任务、子任务、完成、编辑和移动。
- 可切换“包含所有后代目标任务”的汇总模式；默认关闭，防止上下文混乱。

窄屏下改为目标树抽屉 + 详情页签，不保留强制三栏。

### 7.2 任务管理

- 新增“所属目标”列，展示完整目标面包屑。
- 支持按目标及其后代筛选。
- 任务行可展开多层子任务。
- 点击目标面包屑跳转对应目标详情。
- 新建任务可选择目标；在目标页新建时自动锁定当前目标。
- 子任务编辑器显示继承的目标，不允许直接改变归属。

### 7.3 URL 与导航状态

- 目标详情：`/goals/:goalId`。
- 目标任务汇总：`/todos?goalId=:goalId&includeDescendants=0|1`。
- 无效ID显示可恢复空状态，并提供返回目标列表入口。
- 展开状态与最近查看目标单独持久化，不混入领域数据。

### 7.4 创建流程

- 根目标：目标页全局“新建目标”。
- 子目标：目标节点菜单或详情页“新建子目标”，自动设置 `parentGoalId`。
- 根任务：目标详情“新建任务”，自动设置 `goalId`、`parentTaskId=null`。
- 子任务：任务节点“新建子任务”，继承 `goalId` 并设置 `parentTaskId`。

### 7.5 删除与移动

- 删除叶子节点：二次确认。
- 删除非叶子任务：必须选择“级联删除”或“提升直属子任务到当前父级”，默认选择提升。
- 删除非叶子目标：必须选择“级联删除”或“提升直属子目标到当前父级”，默认选择提升。
- 删除目标前列出受影响子目标数、任务数。
- 提升删除目标时，其直属任务改归父目标；若被删目标为根目标，则改为“未归属目标”。
- 级联删除目标时，同时删除其全部后代目标及这些目标归属的任务树。
- 移动目标或任务时实时校验层级、循环和深度限制。

## 8. 前端架构

### 8.1 单一状态来源

- `goalStore`：目标CRUD、树构建、祖先/后代查询、进度汇总、迁移。
- `taskStore`：任务CRUD、任务树、目标筛选、进度汇总、迁移。
- 页面只使用 Store 暴露的命令和派生查询，不直接写 localStorage。

### 8.2 建议模块边界

```text
stores/
  goals.js
  tasks.js
domain/
  hierarchy.js       # 祖先、后代、循环、深度
  progress.js        # 纯函数汇总
  migration.js       # 旧数据到v2
components/goals/
  GoalTree.vue
  GoalWorkspace.vue
  GoalDetail.vue
  GoalTaskTree.vue
components/tasks/
  TaskTreeTable.vue
  GoalBreadcrumb.vue
```

### 8.3 持久化结构

```ts
interface WorkspaceDataV2 {
  version: 2
  goals: Goal[]
  tasks: Task[]
  migratedAt: string
}
```

先继续使用 localStorage，避免本期引入后端；Store 层保留存储适配边界，便于后续切换API。

## 9. 数据迁移与回滚

1. 读取旧 `goals` 与 `todos`，先生成只读备份键。
2. 旧目标补充 `parentGoalId=null`、`manualProgress`、权重和时间字段；旧进度写入 `manualProgress` 作为迁移保底值。
3. 旧任务补充 `parentTaskId=null`、权重及标准时间字段。
4. 已存在且有效的 `goalId` 保留；仅有 `goalTitle` 不进行模糊匹配，避免误关联。
5. 无效 `goalId` 保留原值到迁移诊断信息，业务数据中转为 `goalId=null`。
6. 校验ID唯一性、引用完整性、循环和数量一致性后写入V2。
7. 迁移失败时不覆盖旧数据；用户可从备份恢复。

## 10. 异常与边界状态

- 父节点缺失：节点进入“待修复”分组，可移动回根级。
- 发现循环：拒绝写入并恢复操作前状态。
- 达到20层：禁止新增或移动，并说明限制原因。
- localStorage 容量不足：阻止本次写入，保留内存前状态并提示导出/清理。
- 多标签页冲突：V1不自动合并；检测 `updatedAt` 冲突后提示刷新，避免后写覆盖。
- 空目标：展示新建目标入口及最小示例，不展示无意义统计。
- 目标无任务：详情页直接展示“创建第一个任务”。

## 11. 非目标

- 本期不做多父级目标、跨目标共享任务。
- 本期不引入后端数据库、协同编辑、权限和审计。
- 本期不重写AI拆解能力，只让其产物遵循新任务模型。
- 看板和思维导图不是首期默认入口；待核心层级闭环稳定后适配。
- 不同时维护两套目标管理页面。

## 12. 实施阶段

### P0：模型、Store、迁移

- 建立领域类型、层级纯函数和进度规则。
- 合并目标/任务状态来源。
- 实现V2迁移、备份、诊断及回滚。

完成条件：旧数据数量一致；有效关联保留；层级和进度单元测试通过。

### P1：目标工作台

- 目标树、目标详情、面包屑、子目标操作。
- 当前目标下直接创建、查看任务。
- 删除、提升、移动及错误恢复。

完成条件：目标创建—拆解—查看—调整形成闭环。

### P2：任务层级与双向导航

- 多层任务树、目标列、目标筛选。
- 任务到目标、目标到任务双向跳转。
- 任务父级进度与目标进度联动。

完成条件：任务页面可准确识别归属和上下级，更新后所有父级同步。

### P3：辅助视图与体验

- 看板、思维导图适配层级。
- 批量操作、键盘操作、响应式和无障碍。
- 100目标/1000任务性能优化。

## 13. 测试策略

### 单元测试

- 建树、祖先/后代查询、循环检测、20层限制。
- 等权与加权进度、空节点、完成/逾期状态。
- 删除提升、级联删除、跨目标任务迁移。
- V1到V2迁移、孤儿引用、重复ID和失败回滚。

### 组件测试

- 目标树展开、选择、搜索、移动。
- 目标详情创建子目标和直属任务。
- 任务树展开、创建子任务、展示目标路径。
- 删除非叶子节点的两种处理方式。

### 端到端测试

1. 创建三层目标与三层任务。
2. 完成叶子任务并验证所有父级进度。
3. 从任务跳转目标，再从目标定位任务。
4. 迁移一份包含有效和失效关联的旧数据。
5. 刷新页面，验证结构、筛选和最近位置。

## 14. 验收标准

- 任意未达20层的目标可创建子目标和直属任务。
- 任意未达20层的任务可创建子任务。
- 目标页和任务页均可显示完整目标路径并双向定位。
- 父级进度按定义自动更新，无重复计数。
- 刷新后层级、关联和领域状态不丢失。
- 旧数据迁移前后目标/任务数量一致，有效关联一致。
- 100个目标、1000个任务下，展开、筛选、完成任务的交互无明显卡顿。

## 15. 风险与控制

| 风险 | 控制 |
|---|---|
| 两套页面/Store继续并存 | 明确唯一入口和唯一Store，旧实现退出路由 |
| 递归汇总重复计数 | 只汇总直属节点，子树由子节点自身折算 |
| 删除造成数据丢失 | 非叶子节点强制选择处理方式，迁移前备份 |
| 层级过深导致不可用 | 20层硬限制，默认折叠，面包屑定位 |
| `goalTitle`误匹配 | 只信任有效 `goalId`，不按标题自动关联 |
| localStorage长期不可扩展 | 隔离持久化适配层，后续可替换为API |

## 16. 决策记录

- 采用双树，不采用通用节点或关系图。
- 单父级，不支持跨目标共享子任务。
- 父级默认自动汇总；只有无下级的目标允许手动进度。
- 默认只展示当前目标直属任务树，后代目标任务需显式开启汇总模式。
- 首期沿用 localStorage，先解决模型、体验与数据一致性。
